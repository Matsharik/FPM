# PLAN — бэкенд Трека 1 (утверждён 11.11.2026)

Главная инструкция — `docs/BACKEND_PROMPT.md`. Здесь: как именно её выполняем, по фазам.
Решения по ходу работы — в `docs/DECISIONS.md`, состояние на паузах — в `docs/HANDOFF.md`.

## Окружение
- Рабочее окружение: `.venv313` (Python 3.13). Команды: `.venv313/Scripts/python.exe -m pytest -q`.
- Поддержка заявлена для Python 3.11–3.13 (зависимости ставятся готовыми колёсами). 3.15 — только финальная проверка.
- Ветка `backend-v3`, один коммит на фазу («Ф<N>: …»), без push. В `main` не сливаем (слияние команда делает вручную).

## Архитектура

| Пакет | Роль |
|---|---|
| `timeseries/` | ряд и флажки. Не трогаем |
| `graph/` | узлы и связи в памяти, DAG, обходы |
| `network/` | диск: `node.json` v2, `links.json`, `meta.json`, ряды KPI; `jsonio.py` — атомарная запись |
| `core/` | логика: настройки, часы, словарь, статусы, weighted, анализ, прогноз, отклонения, доступ, журнал, заказы, события; `workspace.py` — точка сборки |
| `seed/` | генератор синтетики, сборка `data/` из `config/` |

| `config/` | YAML-исходники конструктора и демо |
| `tests/` | pytest, работают во временной папке |

Корень данных — `data/` (переопределяется `QNET_ROOT`). Старые маршруты `/manager`, `/builder`, `/qc`, а также `demo.py` и `demo_network.py` удаляются (проверки последнего — в pytest).

## Фазы

### Ф0. Основа
Ветка; версии `==`; `settings.yaml` и сервис часов (часы в `data/meta.json`); единый формат ошибок для всех кодов; фабрика приложения без второй сети на импорте; CORS для localhost и монтирование `web/`; правки `print_node` и `Node.directory`; каркас `run.py`.
Файлы: `requirements*.txt`, `pytest.ini`, `.gitignore`, `run.py`, `config/settings.yaml`, `core/{settings,clock,errors,workspace}.py`, `network/{jsonio,meta}.py`, `api/{server,errors,deps}.py`, `graph/`, тесты.
Готово: `pytest` зелёный, сервер стартует.

### Ф1. Модель
Узел v2 и реестр KPI (ряды в `nodes/NNN/kpi/`); `links.json` с весами, `access`, нормировкой и инвариантами при любой записи; запрет цикла, самосвязи, дубля; флажки на узле и связи; монотонные id из `meta.json`; ошибка с подсказкой на `schema_version: 1`; каскады при удалении узла и KPI; запись правок в `audit.jsonl`; маршруты конструктора (узлы, KPI, связи, веса) и контролёра (точки, флажки трёх уровней).
Файлы: `graph/graph.py`, `network/{network,links,flags,errors}.py`, `core/audit.py`, `api/schemas.py`, `api/routers/{builder,qc,nodes}.py`, тесты.
Готово: Σ=1, нормировка при добавлении и удалении, запрет цикла и самосвязи, флажки трёх уровней, id не переиспользуются.

### Ф2. Словарь и статус
`glossary.yaml` (состав раздела 4 промпта), валидация, профили сезона, severity, статус по порогам с откатом на флажки, `compute: weighted` с кэшем, режимы единиц, запрет денег (Р7).
Файлы: `config/glossary.yaml`, `core/{glossary,units,kpi}.py`, `network/status.py`, `api/routers/{glossary,kpi}.py`, тесты.
Готово: 6,4 % при crit 5 даёт `red` без флажка; weighted считает верно; денежная единица отвергается.
**ПАУЗА 1.**

### Ф3. Аналитика
contributions; trace с двумя альтернативами, причинами остановки, зоной как параметром и детерминизмом по `link.id`; прогноз (линейный тренд + сезонность по дням недели, коридор ±1σ, дата пересечения порогов).
Файлы: `core/{analysis,forecast}.py`, `api/routers/analysis.py`, `tests/scenario.py` (мини-организация «Брак»), тесты.
Готово: trace приходит к «Сборка / defect_rate», «Нагрузка смены» видна альтернативой.

### Ф4. Решения
Карточки и таблица переходов (409), автодетекция при записи точек и перемотке, playbook, recheck с историей, портфель, ветки будущего, `/api/demo/advance|reset|clock`, `run.py --reset`. Сюда же — ядро сида (сценарная ветка `org.yaml`, генератор, ветки).
Файлы: `core/{deviations,playbook,demo,orgconfig}.py`, `seed/{generator,build}.py`, `config/{org,scenario_defect,playbook}.yaml`, `api/routers/{deviations,demo}.py`, тесты.
Готово: reset → DEV-0001 → assign → advance 7 → recheck даёт `passed` и `verified`; без assign — `failed`; два прогона совпадают побайтово.
**ПАУЗА 2.**

### Ф5. Доступ и журнал
`users.yaml`, строгий `X-User` (401), матрица прав в одном месте, зоны по `access: inherit`, граничные узлы сверху и снизу, урезание карточек и trace по зоне, фильтр всех списков, 403, чтение журнала, `/api/graph`, `/api/me…`, `/people`.
Файлы: `config/users.yaml`, `core/{access,people,audit}.py`, `api/deps.py`, `api/routers/{auth,graph,audit}.py`, тесты.
Готово: head_prod видит «Поддержку» серой с одним KPI; head_client видит «Сборку» серой без цифр; qc не меняет структуру; журнал пишет открытия и правки; карточку между зонами видит владелец сигнала, первопричины или исполнитель, чужое урезано.

### Ф6. Поток и источники
5 источников, события и аннотации (как флажки на рядах), заказы с 8 этапами по 4 поля и цепочкой `next_order_id`, flow summary, overview с 8 плитками, затронутые заказы.
Файлы: `config/sources.yaml`, `core/{events,sources,orders,overview}.py`, `seed/orders.py`, `api/routers/flow.py`, тесты.
Готово: 4 поля на каждом этапе любого заказа; 8 плиток у директора.

### Ф7. Сид и конструктор
Полная демо-организация (раздел 10.1), все ряды с сезонностью, validate, export, import с `dry_run`, сценарий «Закупки».
Файлы: `config/{org,users}.yaml`, `seed/*`, `core/orgconfig.py`, `api/routers/builder.py`, тесты.
Готово: `python run.py --reset` даёт полную организацию, `validate` чист, export → import идентичны.

### Ф8. Сдача
Финальный `run.py`, README (поддержка 3.11–3.13), `docs/api.md` с примерами из сид-данных, `scripts/smoke_demo.py`, теги и примеры OpenAPI, `BACKEND_REPORT.md`, проверка чистой машины (3.13, дополнительно 3.15).

## Риски
- Объём против срока (13.11): критический путь закрывается к паузе 2, дальше — порядок 9.2 промпта.
- OneDrive: сброс пишет ~300 файлов в синхронизируемую папку; тесты — во временной папке, `data/` можно вынести через `QNET_ROOT`.
- Иерархия только через связи KPI: зона директора покрывает всё, только если от KPI корня есть `inherit`-связи ко всем функциям. Закрыть тестом в Ф7.
- Утечки между зонами: снимок trace в карточке хранится полным и урезается при чтении (Ф5).
- Перепроверка на грани: окно 7 дней включает дни восстановления; кривую `with_action` подобрать с запасом и зафиксировать тестом.
