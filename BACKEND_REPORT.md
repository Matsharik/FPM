## 3. Что урезано и почему

Порядок 9.2 соблюдён, ни один пункт фаз не выброшен. Упрощено:

- **Импорт не транзакционный.** Документ проверяется целиком до первой записи (схема, метрики, деньги, плитки, дубли, циклы, веса, weighted), но если запись всё же упадёт посередине, уже применённые изменения не откатываются (D103).
- **Заказы и события не зависят от ветки демо.** План заказов создаётся при сиде на 15 суток вперёд; перемотка открывает его по часам (D86). Брак в сегменте сценария — только в окне роста до «сейчас»; после назначения действия новых «бракованных» заказов нет и без него. Дальше 15 суток новых заказов нет.
- **Dockerfile** не делался (необязательный второй вариант запуска).
- **Прогноз** — простая модель (тренд + сезонность по дням недели), так и названа в поле `method`.

## 4. Известные ограничения

- Все данные синтетические; пороги и цифры демонстрационные; отделы с `assumed: true` — допущения.
- Деньги выключены по ТЗ (`allow_money = false`); режим `money` только заложен в модель.
- `X-User` вместо входа — только для демо; в продакшне — SSO/AD. Источники — mock; в продакшне — коннекторы только на чтение.
- **Скрытые вклады влияют на выбор пути trace (D73).** Путь выбирается по всем связям (5.1), поэтому то, что trace ушёл в узел вне зоны, и причина остановки косвенно говорят о чужих данных; цифры чужих узлов не отдаются.
- Демо-ветка начинается с суток назначения: точка этих суток уже из `with_action` (D72, решение владельца).
- Смысл этапа 8 «Возврат» (повторный заказ, возврат товара или рекламация) нужно уточнить у организаторов (D87).
- Находки независимой проверки (`docs/FIX_NOTES.md`), которые не исправлялись:
  - №6 — автодетекция срабатывает по уровню, а не по переходу в красное, и при перемотке один раз в конце: закрытая при красном KPI карточка порождает новую, кратковременный выход в красное внутри перемотки теряется, `signal.ts` опаздывает на длину перемотки;
  - №7 — действие, гипотезу и уверенность можно править у `verified` и `closed`; прежнее действие не сохраняется в записи перепроверки;
  - №9 — повторная перепроверка `verified`-карточки после новой карточки по тому же KPI может оставить две открытые карточки на один сигнал;
  - №12 (остаток) — σ при сезонности считается с n−2 степенями свободы (коридор занижен на коротких рядах); дни недели без данных получают поправку 0;
  - №13 — за концом ветки (60 суток) ряд сценария — константа; часы двигаются до записи точек; ручная точка за текущие сутки усредняется с синтетической при перемотке;
  - №14 — ветка переключается только действием на карточке сигнала (не первопричины) и только фактом назначения;
  - №15 (остаток) — у связи к KPI без данных нет признака `no_data` (такая цель выглядит здоровой).
- Перемотка — не больше 60 суток за вызов; ветки будущего — 60 суток.
- Полный прогон тестов идёт 3–10 минут (каждый модуль собирает демо-организацию на 365 дней).
- Сверка с `origin/main` не делалась: `git fetch` в этом окружении зависает без учётных данных (D19).

## 5. Контракт для фронтенда

[`docs/api.md`](docs/api.md) — по каждому режиму раздела 8 (Вход, Обзор, Граф KPI, Детали, Расследование,
Решения, Поток заказов, Источники, Конструктор, Контроль качества, Люди, Словарь, Журнал, Демо) настоящий запрос
и ответ из демо-данных; пересобирается `python scripts/gen_api_docs.py`. Схема — `docs/openapi.json`
(пересобирается `python scripts/export_openapi.py`, тест сверяет её с приложением). Общие правила: `X-User`
обязателен (кроме `/health` и `/api/auth/users`), чужая зона — 403 `out_of_zone`, ошибки
`{"error": {"code", "message", "details"}}`, время ISO-8601 с поясом, единицы `natural | relative`.
