# «Фотопринт» — трекер KPI и решений (бэкенд, Трек 1)

Управленческий слой над пятью системами компании (CRM, поддержка Mary, ERP, 1С, HR):
**сигнал → контекст → причина → действие (владелец + срок) → повторная проверка**.
Конструктор вместо коробки: узлы, KPI, связи с весами строятся через API за минуты.
Бэкенд на FastAPI, данные — JSON-файлы, всё демо детерминировано (фиксированный сид, без сети и LLM).

## Требования

- Python **3.11, 3.12 или 3.13** (проверено на 3.13; более новые версии не обещаем: под них может не быть готовых колёс).
  На других версиях `run.py` останавливается с понятным сообщением; проверить заранее, до установки зависимостей:
  `python run.py --check`.
- Windows, Linux или macOS. Интернет нужен только для установки зависимостей. Node.js не нужен: собранный интерфейс лежит в `web/`.

## Установка (3 команды)

Windows, PowerShell:

```powershell
py -3.13 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python run.py
```

Затем откройте в браузере **http://127.0.0.1:8000/** — это интерфейс «Фотопринт Manage» (адрес печатается при запуске).
Пользователь выбирается на экране входа; пароль в демо не нужен.

Git Bash: те же команды с путём `.venv/Scripts/python`. Linux и macOS: `python3 -m venv .venv`,
затем `.venv/bin/python -m pip install -r requirements.txt` и `.venv/bin/python run.py`.

## Запуск

`python run.py` проверяет версию Python, при первом запуске сам собирает демо-данные в `data/`
(≈10 с), печатает демо-логины и адрес документации и поднимает сервер на http://127.0.0.1:8000.

- Документация API: http://127.0.0.1:8000/docs (контракт с примерами — [`docs/api.md`](docs/api.md)).
- Флаги: `--reset` (пересобрать демо-данные), `--port 8001`, `--host 0.0.0.0`, `--clock 2026-11-23T09:00:00+03:00`, `--data DIR`.
- Тесты: `python -m pip install -r requirements-dev.txt`, затем `python -m pytest -q` (300+ тестов, 3–10 мин в зависимости от машины).
- Весь демо-сценарий одной командой с проверками: `python scripts/smoke_demo.py --start`
  (поднимает свой сервер во временной папке и печатает OK/FAIL по шагам).

## Интерфейс

- `python run.py` — интерфейс на http://127.0.0.1:8000/ (сборка уже в `web/`, Node.js не нужен).
- Путь демо: вход «Генеральный директор» → Пульс → плитка «Качество» → карточка DEV-0001 → «Открыть в дереве» →
  «Назначить действие» → «Перепроверить» → «Перемотать демо-время на 7 дней» → «Перепроверить».
- Для разработчиков: `cd frontend && npm i && npm run dev` (бэкенд на порту 8790), пересборка `npm run build`,
  проверка `npm run verify`.

## Демо-логины

Паролей нет: пользователь называет себя заголовком `X-User` (в продакшне здесь SSO/AD).

| Логин | Роль | Зона |
|---|---|---|
| `director` | admin | вся компания: видит всё, весь журнал |
| `head_client` | admin | «Работа с клиентами» и 6 её структур |
| `head_prod` | admin | «Производство»: Печать, Сборка, ОТК, Склад, сотрудники |
| `qc_otk` | qc | «ОТК»; свой узел — «Контролёр ОТК Иванова» |
| `builder` | builder | вся компания, только конструктор |

## Демо-сценарий по шагам

Сервер запущен (`python run.py --reset`). В PowerShell пишите `curl.exe` вместо `curl`, а `@файл` берите в кавычки:
`-d "@docs/examples/assign.json"`. Тела с кириллицей — только из файла в UTF-8 (`-d @файл`): в Git Bash `curl -d '…кириллица…'` портит текст.
id узлов после сброса всегда одни и те же: «Поддержка» — 5, «Сборка» — 11 (`GET /api/nodes?name=Сборка`).

1. **Обзор** — 8 плиток, «Качество» красная, одно открытое отклонение:
   `curl -H "X-User: director" http://127.0.0.1:8000/api/overview`
2. **Сигнал и причина** — trace от «Поддержка / доля обращений по браку» к «Сборка / доля брака», «Смены» видны альтернативой:
   `curl -H "X-User: director" "http://127.0.0.1:8000/api/analysis/trace?node=5&kpi=defect_tickets_share"`
3. **Карточка** DEV-0001 (создана автоматически), затронутые заказы и подсказка действия:
   `curl -H "X-User: director" http://127.0.0.1:8000/api/deviations/DEV-0001`
   `curl -H "X-User: director" http://127.0.0.1:8000/api/deviations/DEV-0001/orders`
   `curl -H "X-User: director" http://127.0.0.1:8000/api/deviations/DEV-0001/suggest`
4. **Действие: владелец и срок**:
   `curl -X PATCH -H "X-User: director" -H "Content-Type: application/json; charset=utf-8" -d @docs/examples/assign.json http://127.0.0.1:8000/api/deviations/DEV-0001`
5. **Демо-время** — неделя вперёд; с назначенным действием KPI идёт по ветке `with_action`:
   `curl -X POST -H "X-User: director" "http://127.0.0.1:8000/api/demo/advance?days=7"`
6. **Повторная проверка** — `passed`, карточка `verified`; каждый вызов добавляется в историю:
   `curl -X POST -H "X-User: director" http://127.0.0.1:8000/api/admin/deviations/DEV-0001/recheck`
   Без шага 4 та же перемотка даёт `failed`: без решения ничего не улучшится.
7. **Зоны**: `head_client` не видит цифр «Сборки» (403), `head_prod` видит «Поддержку» серой с одним KPI:
   `curl -H "X-User: head_client" http://127.0.0.1:8000/api/nodes/11`
   `curl -H "X-User: head_prod" http://127.0.0.1:8000/api/graph`
8. **Журнал**: `curl -H "X-User: director" "http://127.0.0.1:8000/api/audit?limit=20"`
9. **Поток и источники**: `GET /api/flow/summary`, `GET /api/orders`, `GET /api/sources`, `GET /api/events?type=annotation`.
10. **Конструктор** (роль `builder`): узел «Закупки» → KPI «Входной брак материалов» → связь от «Сборка / доля брака» с весом 0,2 → остальные веса ×0,8 → вклад и trace показывают новую долю. Создать узел:
    `curl -X POST -H "X-User: builder" -H "Content-Type: application/json; charset=utf-8" -d @docs/examples/node_purchasing.json http://127.0.0.1:8000/api/builder/nodes`
    Весь шаг целиком — в `scripts/smoke_demo.py` и [`docs/api.md`](docs/api.md#конструктор). Проверка и выгрузка: `GET /api/builder/validate`, `GET /api/builder/export?format=yaml`, `POST /api/builder/import?dry_run=true`.

Сбросить стенд к исходному состоянию: `POST /api/demo/reset` или `python run.py --reset`.

## Режимы (контракт для фронтенда)

Вход · Обзор · Граф KPI · Детали · Расследование · Решения · Поток заказов · Источники · Конструктор ·
Контроль качества · Люди · Словарь · Журнал · Демо. Для каждого режима — запрос и ответ из демо-данных в
[`docs/api.md`](docs/api.md); схема — `docs/openapi.json` и `/docs`.

## Ограничения и допущения

- **Все данные синтетические** (`"synthetic": true` у узлов, заказов, событий): структура из ТЗ и слов заказчика, отделы с `"assumed": true` — наши допущения, цифры и пороги — демонстрационные.
- **Деньги выключены по ТЗ** («статусы оплат и затрат без абсолютных сумм»): только статусы, доли и индексы; режим `money` заложен в модель, но `settings.allow_money = false`, и запрос `units=money` даёт 400.
- **Вход по `X-User` — только для демо.** В продакшне здесь SSO/AD; источники подключаются коннекторами только на чтение (на стенде — mock).
- **Скрытые вклады влияют на выбор пути trace.** Trace выбирает связь по всем вкладам (так требует раздел 5.1), поэтому то, что путь ушёл в узел вне вашей зоны, и причина остановки косвенно говорят о чужих данных; сами цифры чужих узлов не отдаются (решение D73).
- Время стенда стоит и двигается только через `/api/demo/advance` — так демо воспроизводимо байт в байт.
- Один процесс, JSON-файлы (без БД): для MVP и демо этого достаточно.
